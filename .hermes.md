## Current engine event architecture

`server/event-bus.js` is the central EventEmitter-based event bus.

Engine code publishes through `publishEngineEvent()`.

The generic `engine:event` channel feeds WebSocket broadcasting, while typed events can have independent listeners.

Do not reintroduce the removed manual `engineEvents[]`, `queueEvent()`, `drainEngineEvents()`, or `flushEngineEvents()` pipeline.

Important domain events include:

- `round:started`
- `round:ended`
- `player:eliminated`
- `player:healed`
- `gift:pending`
- `gift:applied`
- `gift:rejected`
- `meteor:impacted`
- `bounty:claimed`
- `boss:spawned`
- `boss:updated`
- `boss:attacked`
- `boss:defeated`
- `boss:escaped`
- `combat:shot`

Meteor impact uses `meteor:impacted`. Do not recreate the obsolete `boss:updated` payload with `reason: 'meteor-impact'`.

## Narration architecture

Narration is hybrid and event-driven.

Fast Path:

- Local phrase pools in `server/narrationPools.js`.
- Used for high-frequency gameplay events.
- Anti-repetition excludes the last 3 templates per category.
- `boss:attacked` with `reason: 'aggro-changed'` is deliberately silent to avoid narration overload.
- Relevant boss attack phases are `attack-warning` and `attack-resolved`.

Slow Path:

- Implemented in `server/narrator.js`.
- Ollama is reserved for high-impact events such as boss spawn/defeat, epic Gifts, and highlighted round winners.
- User-controlled text/names must be sanitized before entering prompts.
- Narration output must never exceed 16 words.
- Ollama timeout is fixed at 1500 ms, followed by immediate local fallback.

Frontend speech queue (`src/audio.js`):

- Only one utterance speaks at once.
- Maximum 4 pending items.
- Fast Path items older than 4 seconds are stale and discarded.
- On overflow, discard the oldest unprotected Fast Path item first.
- Preserve Slow Path/epic/winner/round-end narration whenever possible.
- Web Speech API target settings: rate `1.45`, pitch `1.25`, language `pt-BR`.
- Prefer native `pt-BR` Google/Microsoft/Edge voices when available.

## Gift safety and balancing rules

Do not turn TikTok Gifts into unavoidable pay-to-win mechanics.

Preserve these principles:

- Rose entry boost remains mild and non-stacking.
- Tactical shield/heal is short and capped.
- Speed has a hard server-side cap and short duration.
- Meteors are telegraphed, server-targeted, spawn-safe, and non-lethal.
- Star Power is visual/Hype status and does not multiply competitive score.
- Colossus is collective spectacle rather than purchased guaranteed victory.
- No cashout, real-money reward, external prize, or economic-value reward tied to Gifts.
- Client/admin input must not control authoritative Gift magnitude, duration, or unavoidable attack targeting.
- Stable TikTok identity uses `event.user.userId`; username is display-only.
- Preserve Gift idempotency/combo handling and input sanitation.
